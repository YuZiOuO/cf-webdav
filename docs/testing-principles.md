# WebDAV RFC 测试原则

本文规定本项目自行编写的 WebDAV RFC 测试的规范来源、判定边界和记录要求。

## 原则

1. 每个测试的预期结果以适用 RFC 的具体规范性要求为依据。RFC 示例和其他实现可用于理解场景，但不构成预期结果的依据。
2. 测试通过 HTTP 请求、响应和后续 WebDAV 请求验证服务端行为。断言基于这些可观察结果，不依赖内部状态或实现方式。XML 按命名空间和结构比较，HTTP 字段名按大小写无关规则处理。
3. 优先覆盖适用、可构造且可观察的服务端 `MUST`、`MUST NOT` 和 `REQUIRED` 行为，但不以逐条规范性文字的穷举为目标。`SHOULD`、`SHOULD NOT` 和 `MAY` 不构成强制断言的依据。
4. 每项测试至少记录：稳定标识、RFC 章节、前置条件、HTTP 请求、可观察断言，以及 RFC 允许的替代结果。

## 覆盖与粒度

1. 每项测试对应一个可独立理解的协议情境，而非一个 RFC 条款或单个 HTTP 请求。一个情境包含完成同一协议目的所需的前置状态、连续请求及其可观察后果。
2. 共享同一资源、初始状态和协议目的的必要变体应在一个情境内验证，例如请求头的显式值、默认值及其对应结果。不要为同一情境的相邻变体拆出微型测试。
3. 仅当变体需要不兼容的核心前置状态、独立的请求或响应语义，或会使合并后的场景难以理解时，才拆为不同情境。每个情境的前置、请求和断言应保持内聚，避免为合并而形成难以阅读的长序列。
4. 覆盖以协议行为类别的大体代表性为目标；新增测试必须补足一个未被现有情境代表的确定性行为，而不是仅为了覆盖更多 RFC 句子。
5. 测试实现直接表达协议情境。仅当同一外部可观察语义被多个情境重复使用时，才抽取共享辅助函数；不得为单次使用或假设性的复用建立通用测试框架。
